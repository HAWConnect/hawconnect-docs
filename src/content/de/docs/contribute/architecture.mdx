# Architektur

HAWConnect besteht aus vier getrennten Repositories und einer vom Backend verwalteten PostgreSQL-Datenbank.

| Teil | Repository | Aufgabe |
| --- | --- | --- |
| App | [hawconnect-app](https://github.com/hawconnect/hawconnect-app) | Android-, iOS- und Web-App (Expo, React Native) |
| Backend | [hawconnect-backend](https://github.com/hawconnect/hawconnect-backend) | API, Konten, Synchronisierung, Anmeldeseite und Einlesen öffentlicher Quellen (Bun, Express, Apollo) |
| Console | [hawconnect-console](https://github.com/hawconnect/hawconnect-console) | Verwaltungsoberfläche (TanStack Start, React) |
| Website | [hawconnect-docs](https://github.com/hawconnect/hawconnect-docs) | diese Seite (Next.js, Nextra) |

Das Backend besitzt den Datenbankzugriff. Weder App noch Console erhalten Datenbank-Zugangsdaten. Die Console ruft die Admin-Schnittstelle des Backends auf; jede privilegierte Anfrage wird dort geprüft.

## Datenquellen

Das Backend liest öffentliche Quellen ein: Speisepläne des Studierendenwerks Hamburg sowie öffentliche HAW-Veranstaltungen, HAW-News und Semesterzeiten. Dafür sind keine Hochschul-Zugangsdaten nötig. Direkte, angemeldete Hochschul-Schnittstellen werden nicht verwendet.
